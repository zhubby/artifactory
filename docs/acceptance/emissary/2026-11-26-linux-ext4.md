## 实际结果

执行入口为`check_emissary_ota_filesystem.py`。
选项为`--filesystem ext4 --with-active-spool`。
复用真实下载器、supervisor、采集器和mTLS接收器。

| 阶段 | 观察与判定 |
|---|---|
| 低空间 | 可用32MiB，不足下载预算；HTTP请求未发出，原状态和资产保留 |
| 预检后满盘 | 首字节落盘后施压；余量512KiB，实际写入返回ENOSPC；失败进度已保存，候选未安装 |
| supervisor满盘 | 单字节写入返回ENOSPC，可用空间0；状态写入也失败，当前runtime持续运行 |
| 保存恢复 | 满盘时终态未保存，原状态及下载保护保留；释放压力后保存failed并释放保护 |
| 只读重挂 | 真实EROFS，未发HTTP请求；原状态、资产和源记录保持 |
| 持续采集 | 同Handle两次采集写盘失败，磁盘错误计数为2，原源记录保留 |
| 采集恢复 | 释放空间后同Handle产生新样本；磁盘计数重开后保持，新样本经业务ACK删除本地源 |
| 原队列恢复 | 2份原批次、3份原清单与原操作终态逐项读回；事务提交前保留原字节，提交后ACK删除源 |

全过程保留原ID、时间、摘要与身份配置。
supervisor与持续采集阶段顺序执行。
本次没有发现需修改产品代码的新缺陷。
