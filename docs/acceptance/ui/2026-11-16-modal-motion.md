# 弹窗入场跳位修复 · 2026-11-16

用户反馈弹窗从右下角出现，随后卡顿。已在开启动效的生产预览中复现：通用弹窗与个人设置共用的 `panel-enter` 动画覆盖了用于居中的 CSS `translate: -50% -50%`。动画结束时恢复居中，形成明显跳位。

## 修复与逐帧验证

保持 `translate` 负责定位，动画改用独立的 `transform: translateY(4px)` 与透明度，持续 150ms。设备详情继续使用右侧抽屉；减少动态效果设置继续优先生效。

1440×1000 视口中的快捷面板实际测量：

| 状态 | 修复前左上角 | 修复后左上角 |
| --- | --- | --- |
| 入场首帧 | `(720, 504)` | `(432, 215.75)` |
| 动画结束 | `(432, 211.75)` | `(432, 211.75)` |

修复前横纵方向各跳动约 288px；修复后水平位置恒定，只在竖直方向轻移 4px。另检查动画 0%、25%、50%、99.99% 和结束后的实际边界，确认通用弹窗和个人设置始终居中，设备抽屉保持右侧位置。

新增四项行为测试，覆盖桌面、平板、手机共 12 项：快捷面板、个人设置、设备抽屉、动画中途开启减少动态效果。关闭弹层后验证焦点恢复。旧生产预览中两个居中用例在三个视口均失败，修复后完整动效测试 21 项通过。
