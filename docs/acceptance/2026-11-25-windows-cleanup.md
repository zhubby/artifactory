# Windows 启动清理与在线恢复 · 2026-11-25

`10.102.149.135` 的 `LAPTOP-VFIEIL8E` 已部署修复并恢复正常调度。节点 UUID 保持 `05c69825-ffc7-46f4-88fe-2cdada414b38`。本次时间均为 UTC。

## 根因与实现

原服务在连接控制平面前执行遗留工作目录清理。任务 `27766581-8ed0-49f0-9864-ef634280fb97` 的 `home\AppData\Local\Microsoft\Windows\INetCache\Content.IE5` 是目录联接。联接的 ACL 拒绝 Everyone 的同步与列目录权限。标准库递归删除返回 Windows 错误 5，启动保留 `source-cleanup-blocked` 并退出。SCM 每分钟重试，节点持续离线。

`cleanup.rs` 保留标准库删除作为首选。Windows 访问拒绝后，以不跟随重解析点的属性句柄识别目录联接，仅删除联接本身，再重试标准删除。递归持有真实祖先目录的句柄并禁止删除共享，防止祖先目录被替换。清理不修改 ACL，也不进入联接目标。真实目录访问拒绝仍返回错误并保留任务准入闭锁。

`source::cleanup_attempt` 复用此删除边界。现有任务锁、进程会话回收与闭锁逻辑保持生效。Windows 服务将最新致命错误链与 UTC 时间原子写入配置旁的 `emissary-error.log`，便于识别下次 SCM 启动失败。
