# 托管签名实现计划

目标：租户加密托管 macOS、Android 签名材料，项目设置默认方案，同一构建节点在签名阶段临时领取，验签证据绑定最终制品。

约束：复用租户权限、项目/节点 signing_profiles、mTLS、90 秒执行租约和不可变制品。保留本机签名。私钥不进入 AI、计划、命令记录、源码、制品和日志。可信宿主脚本构成执行边界。用户已追加授权代码审查、修复、合并 main、推送和 Kubernetes 部署。

- [x] 凭据和版本：认证加密绑定租户与版本；验证 PKCS12/JKS 私钥和证书；公开响应仅含元数据；租户管理接口与独立主密钥配置。
- [x] 项目和计划：默认方案按应用平台选择；创建构建冻结版本；Poll/Kubernetes 共用校验；托管签名输出必须显式声明，模型不能省略签名。
- [x] 节点领取：mTLS 节点身份、当前 session、attempt、当前 sign 步骤和双向授权；不通过可重放命令存放秘密。
- [x] 原生执行：任务私有 keystore/Keychain；阶段结束及失败清理；启动清扫和清理失败闭锁；仅签名步骤注入本任务材料。
- [x] 最终证据：原生工具校验最终 APK/AAB/ZIP/DMG，核对证书指纹与公证状态；制品登记及发布校验 SHA-256 和固定版本。
- [x] 控制台：租户凭据和方案、项目默认方案、构建确认与签名状态；中英文本和现有交互规范。
- [x] 验收：加密上下文、导入、租户/节点/租约/阶段拒绝、并发清理、真实测试证书、Rust/Worker/Web 检查；同步 GEB 地图与使用文档。

测试从认证加密上下文、缺少默认签名、非法签名输出和领取授权开始。数据库测试使用隔离 schema；原生验收使用临时测试证书。真实 Developer ID 公证和真实应用覆盖升级需要用户提供正式签名材料与对应设备，不把本机测试证书结果写成正式发布验收。
