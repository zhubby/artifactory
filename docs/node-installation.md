# 安装并加入节点

在租户的构建节点页打开「注册新节点」。
选择节点池、目标系统和架构。
安装版本固定跟随当前部署的 Artifactory 统一版本。
生成后，安装命令与一次性注册凭证在同一弹窗展示。
目标机器不必与打开浏览器的机器相同。

## 配置设备公开地址

进入租户设置的 Emissary 分区，查看设备连接配置。
系统管理员填写目标机器实际可达的设备地址。
例如 `agents.example.com:8443`，或 NodePort 暴露的实际端口。
IPv6 地址使用方括号，例如 `[2001:db8::10]:31443`。
地址不包含协议、路径、查询参数或登录信息。
端口使用 1–65535 的十进制数字，不加前导零。

该配置属于整个部署，保存到业务数据库。
只有全局系统管理员能修改。
租户所有者和管理员能读取，但租户权限不授予系统配置写权限。
地址修改不改变监听端口、网关、DNS 或证书。
管理员须先完成网络暴露，并使地址主机名匹配设备 TLS 证书。

控制台地址与设备地址独立。
界面不从浏览器域名推断设备端口。
配置为空时，加入弹窗显示配置入口并阻止生成命令。

## 准备签名版本

在相同 Emissary 设置页导入正式版本。
发布来源和验签公钥由部署管理员配置。
详见 [Emissary OTA](emissary-ota.md#发布与信任配置)。
首次安装只使用当前租户已导入的同版本发行。
Artifactory 统一版本为 `0.2.0` 时，安装目标也是 `0.2.0`。
发行标签的 `v` 或 `emissary-v` 前缀不改变产品版本。
缺少同版本发行时，界面提示导入并禁止生成命令。
同版本存在多个不同标签发行时，拒绝歧义选择。
旧页面或直接 API 不能绕过同版本校验。
安装选项排除当前信任公钥无法验证的历史版本。
平台覆盖 Linux、macOS、Windows 的 amd64 与 arm64。
安装材料固定版本、平台、大小和 SHA-256。
资产通过制品网关下载，不向设备分发 GitHub 凭证或 S3 凭证。

## 执行安装命令

1. 在目标机器准备专用普通账户及项目所需 SDK。
2. 在弹窗明确选择目标系统和架构。
3. 生成并复制完整安装命令。
4. 在目标机器执行，按提示完成账户和系统授权。
5. 返回节点列表检查节点心跳和工具链诊断。

Linux 使用 systemd，macOS 使用 launchd，Windows 使用 SCM。
服务安装需要目标机器的系统授权。
节点和构建任务以专用普通账户运行。
Windows 服务账户密码只在目标机器输入。
Windows 还需对应架构的 VC++ v14 运行库。
SDK、签名证书、Keychain 和运行库不由安装命令部署。

命令先下载并校验安装脚本，再执行脚本。
脚本核对系统与架构，下载固定资产并核对大小和摘要。
CA 来自当前已认证控制台，命令携带其摘要。
安装脚本不从设备连接地址临时取回并盲目信任 CA。
生产控制台和安装资源使用系统信任的 HTTPS。
使用组织 CA 时，先在目标机器安装组织信任链。
不要跳过 HTTPS 证书校验。

注册后，安装器初始化 OTA，安装并启动原生服务。
工具链诊断反映目标服务账户的实际环境。
安装成功不代表项目所需全部工具链与签名权限就绪。
macOS 后台服务的 Keychain 和签名权限需单独验收。

## 凭证与恢复

一次性凭证绑定当前租户的一个节点池，至多 15 分钟有效。
成功注册后不可再次使用。
凭证截止不晚于下载票据截止。
服务端锁等待消耗有效时间，不延长使用窗口。
弹窗显示服务端返回的过期时间。
过期后重新生成，不使用旧命令重试。

凭证与连接材料可在弹窗内单独查看和复制。
已安装 Emissary 的机器可使用单独的注册命令。
保留配置、CA 和数据目录的实际路径，再执行该命令。
仅注册命令在失败后仍保留 CA，供部分写入的身份使用。
关闭弹窗或切换租户后，浏览器清除本次明文材料。
凭证不保存到浏览器持久存储。

安装器拒绝覆盖现有配置、私钥或原生服务。
重复执行不能重新注册已有节点。
注册后某一步失败时，保留既有身份并按错误修复后续步骤。
已有节点的升级使用 OTA；不要删除身份来重试首次安装。
服务命令和账户准备见 [部署与运维](operations.md#emissary-安装与注册)。

首次安装涉及目标系统的账户、权限与服务。
本地脚本隔离测试不替代三种系统的实际服务验收。
