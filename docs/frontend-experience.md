# 控制台语言、主题与动效

界面采用黑白灰配色、本地 Inter 和 IBM Plex Mono。统一侧栏只呈现当前租户或项目的业务导航，打开设置后替换为当前工作区的设置分区。租户切换器位于顶栏，项目切换器只在项目侧栏出现。具体颜色、排版、组件与响应式规则见[界面设计规范](design-system.md)。业务 API、角色权限、构建与发布状态、日志及用户配置保持原有含义。

## 偏好与翻译

- `next-intl` 提供 `zh-CN`、`en` 词条、参数插值与复数；词条位于 `web/src/messages/`。新增界面文案需同时更新两个语言文件。
- 默认简体中文。`artifactory-locale` Cookie 保存一年，服务端读取以输出 HTML `lang`、标题及初始文案；切换时更新同一 Provider 的状态，不刷新路由或重新挂载业务组件。
- `next-themes` 使用 `artifactory-theme` 保存 `system`、`dark`、`light`，默认跟随系统；启动脚本在首屏应用配色。语义 CSS 变量同时覆盖页面、侧栏、表格、错误、状态和日志区域。
- 动画默认开启，没有动效开关，也不读取旧 `artifactory-effects=off` 值。系统 `prefers-reduced-motion` 自动禁用动画或减少过渡，保留状态文字，不显示提示。
- 登录后的个人菜单只提供个人设置和退出。个人设置默认显示资料，面板内提供资料、安全、偏好和通知分区；偏好只提供语言和主题。账号入口位于桌面工作台侧栏底部；手机工作区、租户大厅和完整通知页的入口位于顶栏铃铛左侧。匿名页面保留同一组偏好字段。面板不会卸载业务页面，见[工作台与个人设置](workspaces.md)。
- 公开文档使用相同字体与黑白灰主题，共享 `artifactory-theme`，支持系统主题变化和跨标签页同步；保留 mdBook 搜索、目录及 Mermaid。
- 日期按所选语言及浏览器本地时区显示；数据计数按语言格式化。仓库、项目名、日志、配置快照、审计 action 及服务端错误详情原样显示；请求错误有本地化标题。
- 网络异常、无错误详情的 HTTP 失败与本地 JSON 格式错误保留翻译键，已显示的错误会随语言切换更新；服务端提供的错误详情逐字保留。

## 动效生命周期

菜单、弹窗和状态切换采用 120–180ms 过渡。首次读取显示内容骨架；前台请求与导航共用延迟显示的顶部细进度条。后台刷新保留已有内容，定时轮询和 SSE 不显示进度条。读取失败后退出骨架，通过顶部通知和重试入口反馈。

侧栏首次等待租户、项目或权限数据时显示导航骨架。切换当前工作区内的菜单保留已有侧栏，由目标页面的数据区域显示骨架。切换租户或项目时使用目标范围的骨架，不展示上一范围的菜单。资源选项、签名预览、邀请、镜像凭据、OTA 与生命周期操作均区分首读、空态和失败。后台刷新不重建已有表单。

租户布局持续挂载工作区外壳。工作区按租户和项目身份隔离，页内路由只切换内容。服务端继续校验地址，非法路由显示 404。

顶栏集中显示全局工具，通知铃铛位于最右。页面动作始终留在内容标题区。项目概览名称旁的空心或实心星标切换现有项目通知订阅，不新增收藏数据。

系统要求减少动态效果时禁用动画，包括骨架脉动与进度缓动，防止侧面板显示偏移的首帧。运行中修改系统动效设置会自动生效。页面不使用装饰画布、极光或聚光效果；React Bits 和 GSAP 已移除。轮询、SSE、语言及主题变化不触发页面入场，构建详情标签切换保留日志节点及订阅。

## 构建过程

构建默认进入过程标签，计划、执行和制品保留为详情入口。
过程只读取真实阶段与执行记录，不推造缺失历史。
源码失败明确标出 AI 规划和构建设备尚未启动。
后台刷新保留标签、展开记录和阅读位置。
旧构建缺少源码明细时明确说明，终态不继续显示“解析中”。

## 构建日志生命周期

运行中的构建通过 SSE 接收状态与日志。构建进入成功、失败或取消状态后，服务端排空已登记日志，再发送 `complete`。控制台收到该事件后停止重连，并切换为历史日志阅读器。

直接打开已结束记录时，控制台只读取一次详情、计划和当前目标的最近一页日志。历史日志按 attempt 和步骤筛选，每页最多 100 块。点击“加载更早日志”才读取下一页，追加后保持阅读位置。标签和偏好切换不重建阅读器。历史日志不自动跟随，也不显示 SSE 连接状态。

已结束构建只在发布状态为 `pending` 时每 3 秒刷新详情。发布完成或失败后停止。重试目标后恢复实时订阅。构建状态与发布状态分别决定日志订阅和发布刷新。

## 构建计划工作台

构建详情首次进入过程标签。后续状态更新保留已选标签。目标合同默认折叠，标题保留构建编号、版本和状态。

计划先呈现摘要和目标方案，再提供原始要求、证据、外置脚本、完整配置与对话审计。桌面通过目标导航阅读方案；平板和手机使用共享下拉。原生步骤按顺序编号，第一步默认展开。命令保留缩进并支持复制。镜像方案显示自己的 Dockerfile、上下文、平台与构建池。

版本选择默认跟随 `current_plan_id`，显式历史选择保持稳定。响应短暂不同步时保留可用内容并显示同步提示。历史版本保留结构化阅读，不叠加当前执行进度；当前版本中沿用的成功目标注明原计划来源。澄清回答在轮询、标签和偏好切换时保留，成功提交后清除。

规划运行时不可用时显示已确认统计。取消、待补充和终态以持久结果为准。对话审计继续按需加载、分页和合并消息分片，终态补读使用后台请求。版本切换不启动构建或修改方案。

## 对话式构建引导

Release 详情中的“发起构建”打开四步弹窗：「源码 → 构建要求 → 交付目标 → 确认」。项目与版本保持只读。步骤导航和底部操作固定，正文独立滚动；进入步骤时聚焦问题标题，并遵循减少动效偏好。

源码支持搜索分支、Tag 或手动输入引用。构建要求提供常用模板与自定义文本。目标类型和常用平台使用卡片，支持多个原生目标、镜像目标或两者混合；精细目标配置在高级设置展开。高级参数只在确认步展开。各步校验当前回答，返回或从摘要修改时保留其他回答，修改完成后返回确认。

`BuildWizard` 保存本次弹窗的回答、引用查询和提交状态。打开弹窗、项目切换或显式刷新触发引用查询，旧请求取消且迟到的响应不覆盖当前项目或手动输入。最终确认前不创建 Build、不调用模型。已修改的弹窗关闭前确认放弃；关闭、刷新或离开后不保存草稿。提交期间禁止重复提交、编辑和关闭；失败保留回答供重试。Release 或项目变为不可构建时，保留草稿、显示原因并禁用最终提交。接口与交付边界见[项目版本交付](release-delivery.md)。

`web/tests/ui/build-guide.spec.ts` 覆盖四步推进、确认前无创建请求、摘要编辑、目标卡片、校验、失败重试、草稿保护和不可构建状态。`build-wizard.spec.ts` 保留 Release 版本、构建合同、发布、参数和权限回归。`build-source-edge.spec.ts` 覆盖大量引用的默认项、搜索、键盘导航及迟到响应隔离。真实 HTTPS/SSH Git、凭据与信任验证位于控制平面数据库测试，需显式提供隔离测试数据库；UI fixtures 不替代这些验证。

## 设备终端工作区

设备运维区打开独立终端路由，设备列表筛选和详情标签卸载不销毁该路由内的渲染器。显式点击创建，只在真实 PTY ready 后显示已连接。终端按需加载 xterm，输出写回调确认字节消费，输入不重放。网络短断最多保留30秒；刷新和离开页面结束会话。
